### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `<absolute-poteto-mode-skill-dir>/scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (principle-build-the-lever), resolving the helper from the loaded skill. Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed (principle-encode-lessons-in-structure). It classifies size, age, merge state, uncommitted work, PR state, and unknown agent liveness, then suggests a bucket. It never scans private session history. `verify-liveness` is not safe-to-delete evidence.
2. The bucket is advice, not permission. Obtain the pinned and active worktree set from the user or exposed authorized status tools and cross-check every candidate. A pinned or active worktree wins over the audit's suggestion.
3. Verify usage before deleting. Use exposed agent status and explicitly supplied in-scope trails to establish liveness. Do not enumerate private conversations or infer liveness from timestamps. If evidence is missing, hold the worktree. Delegate bounded analysis only when permitted, with explicit read-only scope and supported configured agents.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision before removal. `scratch:N` means untracked files, not disposable files. Inspect them and obtain authorization before deleting. Preserve unrelated and in-use work even when the branch is merged.
5. Prune only the authorized, confirmed set with `git worktree remove <path>` or the required host tool. If Git refuses, inspect remaining files and report the blocker. Do not force deletion or recursively remove a surviving directory without explicit confirmation for that exact scope. Branch refs survive. Confirm reclaimed space with `df -h /` and re-list.
6. Simulators and caches are separate deletion scopes. List candidates and obtain the necessary authority before deleting unavailable simulators, old runtimes, build products, or package caches. Do not delete OpenCode service state, databases, session history, user settings, or unrelated application data as cache cleanup.

This playbook deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in use, uncommitted work, untracked files, or unverified liveness).
