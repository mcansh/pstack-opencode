### Orchestrate

**You run the program, never the code. Decide which agent does each piece of work, then check what each one produces.** For a standing project handed to one coordinator chat: multi-day, many stacked PRs, dozens to hundreds of subagents, few human turns. One task driven to a predicate is Autonomous run. One ambitious run that needs a bespoke workflow is figure-it-out. Work that one agent could finish inside the session's budget is not a program.

Run it with the exposed task/delegation tools and their actual schemas, per the [OpenCode runtime contract](../../opencode-runtime.md). Bundled delegate files are prompt templates for an exposed general agent, not agents the plugin registers. Give each delegate the loaded poteto-mode skill's absolute path and an explicit scope. Keep the program's state in an explicitly supplied tracker and store, or project-local gitignored `.pstack/orchestrate/<project-slug>/notes.md`. Give every state file one writer and read only the program's in-scope files. Watch each PR with PR and CI event subscriptions only when the host exposes them. Call no orchestration scripts, run no polling loops, and never relay routine messages or status between agents.

This playbook grants no publication, merge, deployment, deletion, messaging, configuration, or remote-execution authority. Follow the actual user grant and host permissions. Multi-day persistence requires a separate exposed, authorized scheduler or service. Otherwise run bounded work in this session and checkpoint for explicit pickup. After an OpenCode restart, re-query exposed agent or service status and current forge heads; never assume work survived. Use only the active conversation and explicitly supplied in-scope history, never unrelated private sessions or assumed transcript paths.

Use configured roles from `~/.config/pstack/opencode-models.md` if present. `inherit-parent` means the default delegate without a model override under native agent configuration, not a guaranteed model family. Model, reasoning, and speed preferences are native agent settings, not invented task arguments. If delegation or a required independent or different-family verifier is unavailable, record that gate as unverified rather than substituting a provider or claiming self-review is independent.

#### Topology

- **One owner per PR.** The owner is the only writer of its branch and carries the PR from build through authorized landing. Only the owner performs authorized pushes, rebases, or retargets. Closing or retargeting a base PR orphans every PR above it, so the owner does that only on your call within the user's grant. You never author or edit code. Conflicted merges, chain rebases, and fixes go to owners. Give writers exclusive worktrees or files; a task call does not create isolation.
- **A fresh worker for each independent task.** Its kickoff carries everything it needs, including each authorized upstream report it depends on, pasted in full. Workers can't see their siblings. Use an available isolated environment when required; remote workers require an exposed, documented, authorized service and must never receive local credentials. Runtime drivers, simulators, or auth that exists only here may require local work. Pick only available configured agents, per the Subagents section.
- **A sub-coordinator only when one area has many parallel workers.** It owns that area's workers and kickoffs and sends you one rollup, never raw worker reports. Stop at three levels or the host's lower depth limit: you, sub-coordinators, and workers. Flatten when nested delegation is unavailable. Keep at most about ten workers in flight per coordinator, bounded by actual tool capacity, and refill as each finishes when asynchronous execution is supported.
- **Reuse a worker only when new work needs its built state,** such as its checkout, uncommitted changes, or a running process, through a supported resume or fork capability. Otherwise pass authorized saved state to a fresh worker. Never resume or message one merely to check on it; use exposed read-only status tools instead.
- **Each PR gets a verifier that isn't its author,** on a known different model family. The owner merges only with authority and that verifier's pass at the current head. Same-model attempts do not satisfy the different-family gate; leave it unverified if no qualifying agent is available.
- **Start with one unit.** Take it through kickoff, owner, verifier, and authorized landing or handoff before you fan out, so a flaw in the kickoff costs one agent instead of fifty. On near-identical cheap units, the first unit is that test.

#### Supervision

- **Each kickoff names the evidence that proves the work is done,** such as a command and its expected output, a control-skill check, or an artifact. It also names the goal, the paths the worker may and may not write, and the actions it must not take. If you can't name the evidence, the unit isn't scoped yet.
- **Read the diff or the artifact, not only the worker's summary.** Green CI is an input to a verdict, not a verdict. Behavioral work needs more than a type check. Record evidence and verifier verdicts against the PR number and live head SHA in the tracker; blocked or failed verification is not a pass. A new push or restack needs a new verdict. Read a sample of each sub-coordinator's kickoffs while its workers run, and fix its instructions when one fails.
- **Send back work that drifts from scope or grows past what was asked.** Keep only the fixes that block the program, and park the rest as follow-ups.
- **Check a PR's live state before you report on it,** through exposed authorized forge tools, not the worker's last report. Compare current forge head SHAs with any local refs before trusting them. Serialize stack mutations, refresh the base chain after each, and land only the contiguous verified run from the root. Account for every worker you spawned as done, replaced, or absorbed into another worker's scope.
- **Stop or replace a worker that stalls or loops.** Judge it by exposed agent status, pushes, and PR activity, not its status text or transcript timestamps. Stop or isolate the prior writer before replacing it. Retry by cause within the session budget: a smaller scope after a context or memory limit, the same kickoff after a dropped connection, and a corrected invocation or another available configured agent after a tool error. After two retries, drop the unit and replan around it. When a stopped worker returns late, check its result against the PR's current state, and hand any unique findings to a fresh worker.
- **Ask the user only for a real decision or a blocker,** including missing authority or host approval, an irreversible action, a product or preference call that no experiment settles, or a dead end that survived a replan. Rebase mechanics, retries, CI flakes, review triage, and "should I keep going" never reach the user when already within scope and authority.

**Reply:** what landed or reached handoff against the goal, each PR's live state and head-SHA verdict with its link, what was dropped and why, unverified gates or unavailable host capabilities, the checkpoint path, and the decisions waiting on the user.
